# 공연장 통합 좌석 그리드 — offset 계산 규칙

`musical_blocks`의 각 구역은 `offset_x`/`offset_y`로 "그 층 전체 좌표계에서 어디서
시작하는지"를 나타낸다. 좌석 자체의 `grid_x`/`grid_y`는 항상 구역 내부 기준
(1부터)으로만 입력하고 절대 건드리지 않는다 — 화면에 그릴 때만
`block.offset_x/y + seat.grid_x/y`로 합산해서 절대 위치를 계산한다
(`app_v6.js`의 `renderVenueFloorGrid`).

새 공연장을 추가할 때마다 아래 규칙을 그대로 따르면 되고, **특정 공연장을
하드코딩하지 않는다** — 코드는 완전히 일반화되어 있고, 공연장마다 다른 건
`musical_blocks` 테이블의 offset 값뿐이다.

## 기본 단위

- 셀 1칸 = 좌석 1개 폭 (26px, `.floor-grid-seat`)
- `offset_x`/`offset_y`는 정수, 1-index (좌석 `grid_x`/`grid_y`와 동일 기준)

## 가로(offset_x) 규칙

- 왼쪽 구역부터 순서대로 배치: `다음 구역.offset_x = 이전 구역.offset_x + 이전 구역.max_seats + 통로폭`
- **구역 사이 통로(세로통로) 기본 폭은 1칸.** 통로에 열번호 라벨을 넣어야
  하는 공연장은 2칸으로 넓힌다 — 라벨 요소가 그 2칸에 걸쳐(`grid-column:
  X / span 2`) 가운데 정렬되므로 별도 "가운데 칸"을 계산할 필요 없음
  (아래 "통로에 열번호 표시" 참고).
- 화면 양쪽 끝(첫 구역 앞, 마지막 구역 뒤)은 코드가 자동으로 2칸씩
  여백을 추가한다 (`SIDE_MARGIN`, 렌더러가 처리 — offset 계산 시 신경 안 써도 됨).

## 세로(offset_y) 규칙

- **기본은 전부 0 (같은 시작 라인)** — 실제 이미지를 보고 특정 구역이
  다른 구역보다 무대에 가깝거나 먼 경우에만 값을 다르게 준다.
- 자주 나오는 패턴:
  - **대칭 부채꼴(V자)**: 가장자리 구역이 무대에 가장 가깝고(0), 가운데로
    갈수록 1칸씩 뒤로 밀림. 홀수 개 구역이면 정중앙이 최댓값, 짝수 개면
    중앙 두 구역이 같은 값으로 최댓값을 공유.
    예) 세종문화회관 2층(A~G, 7개): A=3,B=2,C=1,D=0,E=1,F=2,G=3
    예) 세종문화회관 3층(A~H, 8개): A=3,B=2,C=1,D=0,E=0,F=1,G=2,H=3
  - **한쪽만 앞으로 나온 구역** (예: 세종문화회관 1층 A/E가 B/C/D보다
    한 칸 무대 쪽): 해당 구역만 나머지보다 offset_y를 1 작게.
  - **세로로 겹쳐진 구역** (예: 디큐브 1층 OP구역이 B구역 위에 걸침):
    OP처럼 별도 티어인 구역은 offset_x를 겹치는 구역과 맞추고
    (가로 위치만 맞추면 됨), offset_y는 아래 "구역 간 세로 간격" 규칙을
    따라 충분히 띄운다.

## 구역 자기 라벨과 좌석 사이 간격 (모든 공연장 공통, 코드가 자동 처리)

⚠️ **정정 (2026-08-21): 아래는 예전에 "붙어있다"로 잘못 적어놨던 내용을
실제 렌더러 코드(`LABEL_ROW=1`, `SEAT_ROW_START=1`)와 실제 화면 기준으로
다시 확인해서 고친 것 — NOL 씨어터_우리카드홀에서 이 부분을 잘못 계산해서
OP-A/B/C 사이 간격이 0이 되는 실수가 있었음.**

렌더러 상수가 모든 구역에 동일하게 적용된다 — offset_y 계산 시 이 부분
자체는 신경 쓸 필요 없지만, **구역 라벨과 그 구역 첫 좌석 행 사이에는
이미 1행이 끼어 있다** (라벨이 자기 행을 하나 차지하고, 좌석은 그 다음
행부터 시작):

```
row  offset_y + 1              →  구역 라벨(A/B/C...)
row  offset_y + 2  (grid_y=1)  →  좌석 1행
...
row  offset_y + 1 + total_rows →  좌석 마지막 행
```

## 구역 간 세로 간격 (수동으로 offset_y에 반영해야 함)

서로 다른 offset_y를 가진 두 구역이 세로로 이어질 때(예: OP 아래 B),
**앞 구역의 마지막 좌석 행과 다음 구역의 라벨 사이에 최소 1칸의 빈 줄을
남긴다.** 위의 "라벨=자기 행 하나 차지" 특성 때문에, 공식은:

```
다음구역.offset_y  =  이전구역.offset_y + 이전구역.total_rows + 2
```

계산 예 (예술의전당 O→A/B/C, 실제 적용된 값):

```
O: offset_y=0, total_rows=3
  → O 라벨 = 1행, O 좌석 = 2~4행 (offset_y+2 ~ offset_y+1+total_rows)
  → A/B/C.offset_y = 0 + 3 + 2 = 5
  → A/B/C 라벨 = 6행 (5행은 빈 줄)
```

⚠️ **OP처럼 다른 구역 위에 자리를 비워둔 구역은 `is_visible = true`여야 한다.**
`is_visible = false`면 그 구역은 아예 안 그려지는데, 아래 구역들의 offset_y는
여전히 그 자리를 비워둔 채로 남아있어서 — 화면에는 그냥 정체불명의 빈
여백으로만 보인다 (샤롯데씨어터에서 실제로 겪은 문제).

## 통로에 열번호 표시 (`label_position`, `show_row_label`)

일부 공연장(예: 디큐브)은 구역 사이 통로에 그 구역의 실제 행 번호
(row_num)를 보여줘야 한다. `musical_blocks` 컬럼으로 제어:

- `label_position`: `'left'` | `'right'` | `'both'` | `NULL`. 해당 구역의
  오른쪽/왼쪽/양쪽 통로에 그 구역의 row_num을 행마다 하나씩 표시 (라벨이
  통로 2칸에 걸쳐 가운데 정렬됨).
- `show_row_label`: 기본 `true`. 라벨을 아예 끄고 싶으면 `false`.
- 라벨을 쓰는 통로는 **가로 통로 폭을 정확히 2칸으로** 잡는다 — 3칸,
  3.5칸 등으로 여유 있게 잡지 않는다. 옆 구역을 다른 구역과 가운데
  정렬하려다가 이 2칸 규칙을 깨는 실수를 한 적이 있음(GS아트센터
  OP-A/OP-C를 A/C 폭 중앙에 맞추려다 통로가 3~3.5칸이 됐던 사례) —
  중앙 정렬이 필요해도 인접 구역과의 통로 폭은 항상 2칸 그대로 두고,
  필요하면 반대쪽(바깥쪽) 여백으로 조정한다. 라벨을 안 쓰는 통로는
  기본 1칸으로 충분.
- **양옆 구역 중 행이 더 많은 쪽 데이터로 통로를 채운다.** 한 통로를
  사이에 둔 두 구역의 행 수가 다르면(예: B가 OP행 포함 22행, A는 20행),
  적은 쪽(A) 기준으로 라벨을 채우면 많은 쪽(B)의 남는 행(OP, 21행)에
  라벨이 안 뜬다. 이럴 땐 적은 쪽은 `label_position = NULL`로 끄고, 많은
  쪽에 `label_position = 'both'`를 줘서 그 구역 데이터로 양쪽 통로를
  전부 채운다.
- 라벨은 좌석 데이터(`musical_seats.row_num`)가 있어야 실제로 보인다 —
  구역만 만들어두고 좌석을 아직 안 넣었으면 통로만 넓고 라벨은 안 뜨는 게
  정상이다.

## 구역 이름표 숨기기 (`show_block_label`)

실제로는 A/B/C 같은 구역명이 없는 공연장(예: 블루스퀘어)도 있다. 이럴 땐
`block_code`를 그냥 내부 관리용 숫자/코드로 넣고(예: '1','2','3'...),
`musical_blocks.show_block_label = false`로 해서 화면 위쪽 큰 이름표
자체를 숨긴다 — 기본값은 `true`(항상 표시).

## 지금까지 적용한 공연장 예시

| 공연장 | 층 | 패턴 |
|---|---|---|
| 세종문화회관 | 1층 (A~E) | A/E만 B/C/D보다 한 칸 앞 |
| 세종문화회관 | 2층 (A~G), 3층 (A~H) | 대칭 부채꼴(V자), 가운데가 가장 뒤 |
| 디큐브 링크아트센터 | 1층 (OP,A~C) | OP가 B 위에 걸침, A/B 통로에 열번호 |
| 디큐브 링크아트센터 | 2층 (A~C) | A/B/C 전부 같은 시작 라인 |
| 샤롯데씨어터 | 1층 (OP,A~C) | OP가 B 위에 걸침(반드시 is_visible=true여야 자리가 채워짐 — 꺼져있으면 빈 여백처럼 보임), A/B 통로에 열번호 |
| 샤롯데씨어터 | 2층 (A~C) | A/B/C 전부 같은 시작 라인 |
| 예술의전당 CJ 토월극장 | 1층 (B기준) | B열 기준 정렬 |
| 예술의전당 CJ 토월극장 | 2층 (A~C) | A/C가 1~4행, B는 5행부터 시작 (B가 더 뒤에서 시작) |
| 예술의전당 CJ 토월극장 | 3층 (A~C) | A/C가 1~2행, B는 3행부터 시작 |
| 충무아트센터 대극장 | 1~3층 (A~C) | 전 층 A/B/C 시작 라인 일치, B가 `label_position='both'`로 A/B, B/C 통로 열번호 담당 |
| 충무아트센터 중극장 블랙 | 1층 (A~C) | 반원형이지만 직선(ㅡㅡㅡ)으로 단순화, A/B/C 전부 같은 시작 라인, B가 `label_position='both'` |
| 블루스퀘어 우리은행홀 | 1~3층 (좌우 3구역씩) | 실제 구역명이 없어 `block_code`는 내부 관리용(A/B/C), `show_block_label=false`로 이름표 숨김. 1층은 실제 사진 속 계단식/23열 특별석 구조 대신 단순 26행 균일 사각형으로 유지하기로 함(사용자 확정), 대신 A는 23열까지 실좌석이 있고 B는 22열까지만 있어서 **양쪽 끝(A/C)이 각자 자기 옆 통로를 담당**(`A.label_position='right'`, `C.label_position='left'`, `B`는 NULL) — 가운데 구역 행 수가 더 적으면 이렇게 바깥쪽 구역 기준으로 몰아줘야 함 |
